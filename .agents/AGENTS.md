# Reglas de Desarrollo

- No detener el desarrollo para solicitar aprobación por cambios menores.
- Si la mejora no rompe la arquitectura principal: Implementarla, Documentarla, Informar el cambio.
- Solo detener el desarrollo cuando: Sea necesario modificar la filosofía del producto, Cambie la arquitectura del Executive Engine, Exista una decisión de negocio importante, Exista riesgo de romper compatibilidad.
- En cualquier otro caso: Corregir y ejecutar.
